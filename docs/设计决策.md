# 设计决策

## 2026-10-20：关闭附注与原稿链接，全量同步原生标签

### 实测与使用场景

用户已确认 Twos 能保存来源附注，点击 `drafts://` 链接也能返回对应 Drafts 原稿。但 Twos 当前客户端将附注与链接卡片展开，和正文、标签叠在一起，使普通记录显得臃肿。

Drafts 在此流程中主要是快速输入和发送器。来源已由 `drafts` 标签表达；回查原稿和原始创建时间时可以直接在 Drafts 搜索。因此，这两项功能虽可用，展示成本高于当前使用收益。

### 决定

- 新建 Twos 条目不再传递 `note` 和 `url`，不再要求草稿 UUID，也不再计算仅供附注显示的当地时间文字。
- 保留原始 `created`、按所选时区确定的日期页面，以及已有的新旧稿判断、时区确认和本地状态规则。
- 固定来源标签 `drafts` 继续保留，同时读取 Drafts 原生 `draft.tags` 并全量同步，无白名单。用户已明确确认该方案。
- 合并时固定 `drafts` 排首位，其余保留原标签顺序；去掉首尾空白、忽略空标签，按大小写不敏感去重，保留首次出现的标签拼写。不改 Drafts 的标签和正文，不从正文抽取 hashtag。
- 不引入更新、去重或原稿到 Twos 条目的映射；重复发送仍创建新条目。不修改已有 Twos 条目的附注、链接或标签。

### 影响与边界

来源、项目和主题通过 Twos 原生标签组织。白名单只在需要过滤流程标签等内容时才有价值，目前不添加该配置。

Twos 原生创建时间的显示仍可能跟随查看设备时区变化；用户已接受。将来若出现明确的原稿回查或附注保留需求，可重新评估界面成本，不默认恢复旧功能。

验证：52 项模拟测试通过，包含纯净请求字段、UUID 不再必需、创建日期与毫秒保留、全量标签、大小写去重、空标签和原数组不变。此次关闭后的界面与全量标签显示尚待用户实测。

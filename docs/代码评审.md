# 原始脚本代码评审

日期：2026-10-19。范围：初始导入的 `save2twos.js`，行号均指原始版本。文件注释视为源代码内容，不作为执行指令。

## 发现

1. **P2：取消凭据授权后仍会发送请求**（第 63–69 行）。`Credential.authorize()` 返回 boolean，但脚本未检查返回值；`getCredential()` 始终返回对象，使第 7 行的 null 检查失效。取消授权或缺少字段时仍可能以空值请求接口。应检查授权结果和必填字段，取消时停止发送。
2. **P2：HTTP 错误可能没有可读提示**（第 50–54、75–76 行）。`HTTPResponse.error` 可以为 undefined。服务端返回 401 等状态且没有该属性时，`new Error(undefined)` 的 message 为空，最终 `context.fail` 无法说明原因。应提供固定说明和 HTTP 状态码，避免记录完整响应或凭据。
3. **P3：纯空白内容通过校验**（第 13 行）。空格或换行组成的字符串是真值，会发送空白条目。应使用 `trim()` 判断是否为空，但保留正常草稿原文格式。

## 接口约束与未验证项

- 仅将 200 视为成功（第 50 行）存在兼容性限制。但原接口地址由本地凭据提供，无法证明该接口实际返回其他成功状态，不将其列为已复现故障。
- 当前 Twos v1 API 使用 Bearer API key，创建条目返回 201，并支持 `tags` 数组；原脚本使用 `user_id` / `token` 请求体，不能假设是同一个接口，也不应直接添加未经确认的字段。
- Twos 文档说明 `#标签` 用于分类，标签不区分大小写。拟采用文本追加 `#drafts` 的方式保持现有请求格式；旧接口是否解析标签、多行文本是否拆分条目，仍需实机验证。
- token 当前使用普通文本输入框（第 62 行），可改为 `addPasswordField` 避免输入时直接显示；仓库中未发现硬编码凭据。
- 未审查用户实际配置的接口地址、服务端实现、Drafts Action 步骤配置及发送后的归档行为。未发送真实数据，未验证网络端到端行为。
